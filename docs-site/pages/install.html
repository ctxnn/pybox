You don't need Docker Desktop. PyBox uses its own private Colima profile and never touches your existing Docker setup or contexts.

1. Install PyBox

That gives you the pybox command (pybox --version to check). PyBox has no dependencies. The package is called pybox-sandbox on PyPI because the name pybox was taken; the command is pybox and the Python import is import pybox.

2. Preview the setup

This is a dry run. It checks your Mac and lists every folder and file it would create, then explains what would happen next. Nothing changes yet.

3. Build the sealed box

PyBox now:

  1. Creates a private folder at ~/.pybox/runtime, readable only by you.
  2. Starts a dedicated virtual machine called pybox, with no shared folders and no forwarded ports.
  3. Downloads exactly one image: a specific Python image, pinned by its fingerprint (digest), so it can't silently change.
  4. Verifies everything, then stops the VM again.

On the build machine, a fresh setup from nothing took 3 min 17 s (21 October 2026), most of it the VM download. Setup prints how long it took and what to run next.

Run it again any time. It never overwrites a file that already exists. If a file differs from what it expects, it stops and tells you which one.

Optional: numpy and pandas

Builds the data image from hash-locked wheels, in about 30 seconds. You can do it during the first setup or any time later.

4. Check it

doctor is read-only. Every line that isn't ready says what to run next. The engine and image checks can only pass while the VM is running. Add --json for a machine-readable report.
