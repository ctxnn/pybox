An independent review session read the new code adversarially before release. It found no way for a program or agent to reach the Mac's files, the network or past the server's ceilings. It did find 2 medium issues (a program could forge the terminal receipt, or blank the MCP receipt with crafted file names), 6 low and 6 informational ones, and 11 places where the docs said more than the code did. All are fixed or documented, with regression tests; see docs/M10_SECURITY_REVIEW.md in the repository.

What is assumed

  • The virtual machine is healthy and keeps getting CPU time. If your Mac sleeps, time in the box pauses too.
  • Nothing outside PyBox tampers with the box's timer or the VM.
  • The Docker command-line tool reports errors in its usual English wording. PyBox relies on that wording in one narrow case.

What is not claimed

  • That the box resists every possible attack. Thirteen checks prove thirteen cases.
  • Exact real-time limits, or exact final resource counts.
  • That PyBox works with every MCP app. It was tested with its own client, Claude Code and Cursor's command-line agent, not Claude Desktop or the official SDKs.
  • That returned files are trustworthy. They are the program's work, carried by a helper running as the program's own user.
  • That the AI repair results generalize. Four problems is an example.
  • That setup has been proven on a second Mac. It's unit-tested, and an end-to-end run on another machine is the next milestone.
  • Anything about cost. Unknown costs are recorded as unknown.
