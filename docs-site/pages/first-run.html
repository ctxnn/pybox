1. Start the box

This boots the private VM and checks its settings: no shared folders, no forwarded ports, the pinned image present. If anything is off, PyBox stops the VM again and says why. No other command ever starts the VM for you.

2. Run a program

Give PyBox a file, or - to send the program on standard input:

In about a third of a second, PyBox builds a fresh box, runs the program, removes the box, and prints what the program printed, then a short receipt. The command's exit code is 0 when the program exited 0. The exit codes tell you at a glance what happened.

The short receipt is a view. Add --json to get the full record it's built from.

3. Read the receipt

Here's the full record (pybox exec - --json) of a program that printed hello inspection, recorded on 19 October 2026 and trimmed to the parts that matter:

Read it top to bottom as four questions:

SectionThe question it answersIn this run
configuredWhat did PyBox ask for?2-second limit, 128 MB, no network, a non-root user, read-only files.
observedWhat did the engine and the kernel actually see?The settings were verified before starting. The program exited 0 after 0.075 s. Memory peaked around 4 MB.
captureWhat did the program say?hello inspection. This is the program's own output, so it's labelled untrusted.
unknownWhat can't PyBox be sure of?The exact final memory count, the exact cause of termination, and whether the clocks line up.

Why "unknown" is always there. PyBox reads memory and CPU counters while the program runs, but the box can vanish between two readings. So it reports the last value it actually saw and says the final one is unknown, instead of quietly calling the last reading final.

For a field-by-field guide, see The receipt.
