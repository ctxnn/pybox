You set the ceilings

The person who configures the server decides what an agent may ask for. An agent can only ask for less.

Server optionDefaultMeaning
--max-timeout S2The longest run an agent may request, up to 30 seconds
--images LISTstdlibWhich images an agent may use: stdlib, data, or ones you built. Images

The tool's schema shows the agent exactly these limits, and every call is checked against them again on your Mac.

The tool

ArgumentRule
code (required)Python source, at most 65,536 UTF-8 bytes
timeout_sMore than 0, at most the server's --max-timeout (default 2)
max_output_bytes1–8,192 per stream (default 4,096)
imageOne of the server's --images (default stdlib)
filesUp to 16 input files, {name, content, encoding} with encoding utf-8 (default) or base64; 256 KiB in total. They appear in /tmp/input/
return_filestrue to get back what the program writes to /tmp/output/

Any other argument is rejected. There is no way for an agent to pick a path on your Mac, a shell command, environment variables, or the unsealed runner.

Files

Returned files arrive in structuredContent.files. Names of files that weren't brought back appear in the receipt with unusual characters escaped, at most 16 listed, so they can't crowd out the trusted parts of the receipt. Each returned file has its name, bytes and sha256, and its content, as text when it's valid UTF-8 and base64 otherwise. File contents are capped at 48 KiB in total so the whole result fits the protocol's frame. Larger files are still listed, with their size and SHA-256, marked omitted. Like stdout, returned files are the program's work: untrusted data. See files in and out for how they travel.

Output is data, never instructions

MCP uses standard output for its own messages. If a program's output went straight there, a program could forge a protocol message. PyBox never lets that happen: the program's output is nested inside the tool result as a string.

In a recorded test, a program printed a fake protocol response with id 999. It arrived only inside capture.stdout, and the client received no message with id 999.

This protects the protocol, not the model. Your agent still reads that output and those files. Treat them like any untrusted text: they may contain instructions aimed at the model. PyBox keeps them clearly labelled; it can't make a model ignore them.

What the result looks like

Each call returns structuredContent with {schema_version, execution, delivery}, plus files when you asked for them, and the same JSON as text. execution is the receipt. If it ever can't be delivered, the error still carries the real cleanup status. delivery says whether anything was trimmed to fit. isError is true when the program failed, timed out, was cancelled, or cleanup wasn't confirmed. Read the receipt to see which.

Cancelling

A cancellation from the client, closing the connection, or stopping the server all stop the running program and clean up its box. A cancelled call gets no response, as the protocol expects; the server reports the cleanup result on its error stream.
