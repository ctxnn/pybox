What made it faster

The first measurement (M9) took 0.316 s per run, and almost half of that was arming the kernel watcher: 0.146 s. Nearly all of it went to starting colima and Lima's helper programs before the SSH connection, which Lima already keeps open. PyBox now runs /usr/bin/ssh over that open connection itself, which takes 4–9 ms. It reads only four values from Lima's SSH settings (user, port, key and connection socket) and checks each one against what this installation expects. If any check fails, it falls back to colima ssh. The receipt records which way the watcher was reached (configured.watcher_transport).

Why there's no pool of ready boxes

Keeping boxes pre-built would save a few hundredths of a second per run. It would also mean a box could exist before you asked for it, with settings checked at some earlier time, and possibly reused. "Fresh every time, checked just before it runs" is the point of PyBox. At about 0.2 s per run, giving that up isn't worth it, so PyBox doesn't do it.

Reproduce it

Each benchmark run is a real sealed run, so the usual rule applies: one run at a time per installation.
